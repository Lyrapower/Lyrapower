# 一个 234 KB 的 Python 游戏是怎么做出来的

写给想自己做一个学习小游戏的新手。蟒行记整个游戏是一个 233,723 字节的 HTML 文件，里面有 327 张代码卡、6 夜像素关卡、配乐和 WebGL 光照，没有图片和音频文件，不用服务器。下面按顺序讲它是怎么来的，以及每一步为什么这么做。

## 1. 先想清楚"为什么停不下来"，再想教什么

第一版是一个马里奥式的小游戏，题目塞在关卡里。玩起来像做作业：题少，画面粗，打开一次就不想再打开。第二版改名蟒行记，画面和玩法还是像十年前的东西。

第三版换了出发点：先不问"Python 该按什么顺序教"，先问"人为什么会刷短视频刷到停不下来"。拆开来是四件事：

- **每一下都很短**。一张卡几秒钟，等一趟车能刷十几张。
- **马上有反馈**。答对有连击、萤火、偶尔出金卡。
- **不知道下一张是什么**。新卡和旧卡穿插着出。
- **天天来有记录**。连日计数。

所以蟒行记的主界面是"刷"：一屏一张代码卡，猜输出，上滑下一张。闯关只在你想玩久一点的时候才开。

## 2. 忘了的会回来：遗忘曲线

记住一张卡靠的不是看一遍，是在快忘的时候再见一次。蟒行记的排期在 `src/reel.js` 里，规则很简单：

- 答错：过 4 张卡再出现；
- 答对：间隔逐级拉长，1 天 → 3 天 → 8 天 → 20 天；
- 新卡和到期的旧卡穿插着出，大约七成概率先出到期的。

不需要服务器，进度存在你自己的浏览器里（localStorage），不用注册。

## 3. 卡片是纯文本，谁都能加

327 张卡写在 `src/cards.txt` 里，一张卡长这样：

```
%%
a = [1, 2]
b = a
b.append(3)
print(a)
= [1, 2, 3]
? [1, 2] || [3]
! b = a 只是多一个名字,指向同一个列表。
```

`%%` 分隔卡片，`=` 后面是答案，`?` 后面是干扰项（用 `||` 隔开），`!` 后面是答完显示的一句讲解。想补卡的人不用懂 JavaScript。

## 4. 答案不靠人核，靠 Python 自己跑

学习类游戏最怕的是答案写错：你答对了，它说你错，你从此不信它。

`test/check_cards.py` 把 327 段代码逐段用真的 Python 执行，比对卡上写的答案，有一张不符就失败。规则有三条：

- 答案是异常名的卡（`TypeError`、`KeyError`……），代码必须恰好抛出这个异常；
- 答"正常运行"的卡，必须既不输出也不报错；
- 正确答案不许同时出现在干扰项里。

它确实抓到过一张错卡：

```python
nums = [3, 1, 2]
print(f'{max(nums)=}', f'{len(nums):>3}|')
```

卡上写的答案是 `max(nums)=3 3|`，真跑出来是 `max(nums)=3   3|`。`>3` 的意思是右对齐、宽度 3，所以数字 3 前面要补两个空格。

这张卡改正以后，原来那个错答案留下来当干扰项，正好考 `>3` 这个点。现在 327/327 全对，每次改卡都重跑。

**给新手的一句话**：AI 帮你写题很快，但 AI 写的答案也会错。能让机器执行核对的，就别靠眼睛核。

## 5. 为什么是一个 HTML 文件

源码分开写在 `src/` 里：

| 文件 | 内容 |
| --- | --- |
| `game.js` | 关卡与操作 |
| `fx.js` | WebGL 光照；老设备自动退回 2D |
| `mus.js` | 程序生成的配乐，没有音频文件 |
| `reel.js` | 刷卡与排期 |
| `content.js`、`cards.js` | 关卡题与卡片 |
| `ui.css` | 样式 |

`build.py` 只有 18 行，把它们拼成一个 `dist/index.html`，不需要 npm 和打包工具。

一个文件的好处：

- 双击就能打开，发给别人就是发一个文件；
- 放到 GitHub Pages 上就是一个网址；
- 体积小，手机流量不心疼。

像素画、光照、音乐都用代码现场生成，所以没有图片和音频文件，体积能压到 234 KB（gzip 后约 79 KB）。

## 6. 飞机上也能玩：离线不是写一句"支持离线"

`build.py` 还会生成一个 service worker（`sw.js`）：

- 有网时先取最新版，再存一份；
- 没网时用存下的那份。

每次构建的缓存名带上内容的哈希，改版以后旧缓存会自动换掉。

验证的办法是真的把网断了：`test/offline.cjs` 先打开一次页面，再切断网络，重新打开，确认游戏还能玩。如果把 service worker 去掉，这个测试会失败，说明它测的是真东西。

## 7. 测试：让浏览器自己玩一遍

用 Playwright 开一个真浏览器，像玩家一样按键、点卡：

| 测试 | 测什么 | 项数 |
| --- | --- | ---: |
| `test/e2e.js` | 关卡玩法 | 58 |
| `test/e2e_reel.js` | 刷卡、排期、连击 | 29 |
| `test/e2e_v3.cjs` | WebGL 呈现层 | 20 |
| `test/offline.cjs` | 断网后重开 | — |

再加上 `check_cards.py` 的 327 张卡。

## 8. 如果你也想做一个

1. 先写下"为什么停不下来"的四件事，每件对应一个具体的界面动作。
2. 内容用纯文本格式写，让不会编程的人也能加。
3. 答案让机器核，写一个脚本把所有题跑一遍。
4. 能用代码生成的就不放素材文件，最后合成一个 HTML。
5. 每说一句"支持 XX"，就写一个能失败的测试去证明它。
